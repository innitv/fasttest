# Демо оплаты для подрядчиков

Кликабельное демо одного сценария: пользователь платит на стороне подрядчика,
переходит в интерфейс банка, подтверждает платёж и возвращается обратно.
Демо показывает **смену айдентики** на маршруте: экраны подрядчика оформлены
его темой, экраны банка — своей, и токены этих двух слоёв не пересекаются.

Демо ничего не оплачивает: это макет в браузере, без сети, платёжного
провайдера и хранения данных.

Поставляются две калибровочные темы:

| Ссылка | Подрядчик | Архетип экрана |
|---|---|---|
| `/flowwow` | Flowwow | корзина, оформление заказа |
| `/uchi` | UCHi.RU | оплата подписки |

Корень `/` и любой неизвестный путь отдают нейтральную заглушку: подрядчик,
получивший свою ссылку, не видит существования второй темы.

## Запуск локально

Нужен Node.js 22+ и yarn 1.

```bash
yarn install
yarn dev          # http://127.0.0.1:5173
```

Сборка и предпросмотр продакшн-бандла:

```bash
yarn build        # tsc --noEmit + vite build → dist/
yarn preview      # http://127.0.0.1:4319
```

## Параметры адреса

Тема и архетип задаются путём (`/flowwow`, `/uchi`); query уточняет состояние.

| Параметр | Значение | Зачем |
|---|---|---|
| `?stage=` | `contractor`, `ozon_rail`, `push`, `splash`, `bank_payment`, `bank_success`, `paid` | Открыть конкретный шаг маршрута, не проходя его руками |
| `?state=` | `handoff`, `ozon_selected`, `cta_sent`, `cta_disabled`, `field_error`, `promo_open`, `phone_expanded`, `phone_checking`, `phone_error` | Показать оверлей перехода и прочие промежуточные состояния |
| `?a11y=` | `enforced` (по умолчанию), `donor_faithful` | Переключить режим контраста: с принудительными коррекциями до порогов либо как у донора |
| `?archetype=` | `cart_checkout`, `subscription_payment` | Проверить тему на чужой раскладке |
| `?t=` | base64url от JSON-конфига тенанта | Отдать демо со своей темой ссылкой, без пересборки и деплоя |
| `?tenant=` | `flowwow-like`, `uchi-like` | Явный выбор поставляемой темы (путь обычно удобнее) |

Некорректный конфиг в `?t=` не приводит к белому экрану: показывается экран
диагностики с кодом ошибки (`E_URL_BASE64`, `E_URL_JSON`, `E_OZON_LABEL` и т. д.).

## Проверки

```bash
yarn check:theme   # статическая проверка границы темы, сервер не нужен
yarn preview       # в отдельном окне
yarn verify        # 22 приёмочные проверки в реальном браузере + скриншоты
yarn check:mobile  # 8 проверок в профиле телефона + скриншоты
```

`yarn check:mobile` — отдельная приёмка в профиле устройства (`iPhone 13`:
`isMobile`, `hasTouch`, DPR устройства) с настоящими тач-жестами. Она ловит
то, чего десктопный `verify` не видит по устройству: цвет системных зон
(`theme-color` статичен и бел на всех экранах), захват жеста вложенным
горизонтальным рядом, сдвиг колонки под пуш-баннером, прыжок прокрутки при
появлении пуша (`scrollTop` до и после обязан совпадать до пикселя) и
раскладку экрана успеха на реальной (меньшей) высоте видимой области Safari.
Диагнозы этих дефектов и решение по системным зонам — в `FIXES.md`. Скриншоты и
`mobile-report.json` складываются в `test-results/mobile`; `--base` и `--out`
переопределяются так же, как у `verify`.

`yarn verify` требует установленного браузера Playwright:
`yarn playwright install chromium`. По умолчанию скрипт ходит на
`http://127.0.0.1:4319` и складывает скриншоты и `verify-report.json` в
`test-results/screenshots`. Оба пути переопределяются:
`yarn verify --base=http://127.0.0.1:4320 --out=<папка>`.

`yarn check:theme` защищает архитектурную границу: экран перехода и экраны
банка не читают ни одного токена темы подрядчика (`--t-*`), экран возврата —
ни одного токена банка (`--bank-*`), а строчное написание бренда банка
допускается только внутри слота `BankWordmark`.

## Деплой на Vercel

Настройки проекта:

- **Root Directory** — корень репозитория;
- **Build Command** — `yarn build`;
- **Output Directory** — `dist`;
- **Framework Preset** — Vite (или Other).

`vercel.json` в корне уже задаёт то же самое плюс SPA-rewrites: без них прямой
заход на `/uchi` или `/flowwow` вернул бы 404, потому что маршрут разбирается
на клиенте.

## Структура

```
src/
  App.tsx           лёгкий роутер: путь → тема + архетип, без презентации
  views/            экраны маршрута (подрядчик, банк, возврат) и их хост
  components/       примитивы верстки; components/bank/ — только сторона банка
  theme/            схема tenant.json, сборка темы, диагностика конфига
  content/copy.ts   тексты
  lib/              аналитика (анонимная), маска телефона, скролл
tenants/            калибровочные темы: flowwow-like.json, uchi-like.json
tests/              verify.mjs (приёмка в браузере), theme-boundary.check.mjs
```

## Известные ограничения

- **Платежей нет.** Ни один экран не обращается к платёжному провайдеру;
  подпись «Демонстрация: платёж не выполняется» присутствует на экранах банка
  намеренно и не должна удаляться.
- **Товарные знаки.** Названия и визуальный язык Flowwow, UCHi.RU и Ozon Банка
  применены по решению владельца демо. Перед показом третьей стороне их нужно
  заменить на нейтральные — темы для этого и вынесены в `tenants/*.json`.
- **Изоляция подрядчиков — UX-барьер, а не безопасность.** Обе темы лежат в
  одном бандле; прямые ссылки лишь не показывают одну тему из другой. Если
  нужна настоящая изоляция, это отдельные сборки или отдельные деплои.
- **Телефон не покидает состояние страницы.** Номер не пишется ни в
  localStorage, ни в sessionStorage и не попадает в аналитические события;
  проверка номера — заглушка с фиксированным ответом.
- Демо рассчитано на мобильную ширину; на планшете и десктопе показывается та
  же вёрстка центрированной колонкой не шире 480 px.

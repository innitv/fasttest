# Бренд по домену вместо скриншота — гипотеза, факты и живые проверки

Ось: получить цвета/логотип/шрифты подрядчика по его домену, не разбирая скриншот платёжного экрана.

## Краткий вывод

Гипотеза **жива, но не как замена скриншота — как дешёвая дополнительная сигнальная линия с неполным покрытием**. На шести реальных российских доменах (Сбер, Т-Банк, Wildberries, Ozon, Альфа-Банк, ВТБ), проверенных вживую сегодня, 27 июля 2026: собственное извлечение через `manifest.json` дало **точный** брендовый цвет без единой интерпретации в 2 случаях из 6 (Т-Банк — `#ffdd2d`, Альфа-Банк — `#f03226`), причём в случае Т-Банка это прямо разоблачило вводящий в заблуждение `theme-color` из HTML (`#ffffff` — не бренд-цвет, просто цвет UI-хрома). В 1 случае (Сбер) сам домен подрядчика оказался редиректом на другой домен без единого бренд-сигнала. В 1 случае (ВТБ) манифест сломан (404), доступны только иконки без цвета. В 2 случаях (Wildberries, Ozon) сработала антибот-защита — Wildberries заблокировал даже реальный браузерный сеанс, не только curl. Коммерческие Brand API (Brandfetch, Logo.dev) **не поддаются проверке по РФ-доменам вообще** — оба публичных эндпоинта требуют платный ключ, которого у нас нет; открытых данных об их покрытии `.ru`/`.рф` не найдено ни в одном источнике. Итог: подход по домену стоит внедрять как **предварительный дешёвый шаг перед скриншотом**, а не вместо него.

## 1. Brand API как сервис

### Clearbit Logo API — мёртв, подтверждено несколькими источниками
Сервис официально закрыт после поглощения HubSpot. Собственная страница миграции Logo.dev формулирует это прямо: «The Clearbit Logo API powered company logos for over a decade, then was permanently shut down on December 8, 2025 after the HubSpot acquisition» (logo.dev/clearbit, обращение 27.07.2026). Официальный форум HubSpot Community подтверждает дату отключения — 1 декабря 2025 (community.hubspot.com/t/upcoming-sunset-of-clearbit-s-free-logo-api/128173). Один вторичный источник (salesmotion.io) называет декабрь 2024 — это расхождение с двумя более авторитетными первоисточниками (сам вендор-преемник + официальный форум HubSpot), поэтому декабрь 2025 считаю верной датой, а декабрь 2024 у salesmotion.io — ошибкой этого конкретного источника. **Практический вывод: Clearbit как путь для этого проекта закрыт, не рассматриваем.**

### Logo.dev — официальный преемник Clearbit, пенопись подтверждена с первоисточника
Прямо снял страницу `logo.dev/pricing` (обращение 27.07.2026, полный текст получен). Реальная структура тарифов:
- **Community — $0/год**: Logo API + Search API, 500 000 запросов в месяц (CDN + картинки), коммерческое использование требует видимой ссылки на Logo.dev.
- **Startup — $280/год**: без ссылки на Logo.dev, 1 млн запросов/мес.
- **Pro — $1 260/год**: то же + **Brand API** (это единственный тариф, где отдаются цвета/метаданные, а не просто картинка логотипа), self-host логотипов, 5 млн запросов/мес.
- **Enterprise — от $2 800/год**: кастомные лимиты и эндпоинты.

Отдельно нашёл документацию Describe API (logo.dev/docs/describe/introduction) — по домену возвращает JSON с `colors` (массив `{hex, r, g, b}`), названием компании, соцсетями и логотипом; доступен «on any paid plan», то есть не на бесплатном тарифе.

**Живая проверка:** запросил `https://img.logo.dev/sberbank.ru` напрямую (curl, без ключа) — получил `HTTP 401 Unauthorized`. Это подтверждает документацию (нужен токен), но **не даёт возможности проверить покрытие по РФ-домену** — без платного ключа сервис недоступен для теста вообще.

### Brandfetch — структура подтверждена официальной документацией, цена — только вторичными источниками
Официальные страницы `docs.brandfetch.com/brand-api/overview` и `docs.brandfetch.com/logo-api/overview` открыты и прочитаны (обращение 27.07.2026): Logo API — бесплатный CDN-эндпоинт с client ID, работает по паттерну `https://cdn.brandfetch.io/{domain}`; Brand API — платный, отдаёт логотипы, палитру, шрифты, фирмографику, при этом «if a brand is not part of our dataset, it will index the information live» (живая доиндексация неизвестных доменов — заявлено, не проверено). Тестовые запросы к домену `brandfetch.com` бесплатны без ограничений — это единственный домен, который можно погонять без ключа.

Страницу `brandfetch.com/developers/pricing` открыть не удалось (`Failed to fetch url` у Tavily) — точные цифры тарифов Brandfetch у меня **только из вторичных источников** (context.dev, miromiro.app, brandsapi.com — все три сами являются конкурирующими продуктами в этой же категории и пишут маркетинговые сравнительные статьи, доверие ограниченное). Разные вторичные источники расходятся в цифрах свободного тарифа (от «100 запросов/мес» до «500 тыс. запросов/мес фейр-юз») — это `needs validation`, консенсуса нет даже между вторичными источниками.

**Живая проверка:** запросил `https://cdn.brandfetch.io/sberbank.ru` без client ID — получил `HTTP 302` редирект на `docs.brandfetch.com/docs/logo-link/guidelines#2-hotlinking`, то есть сервис отказывается отдавать лого без параметра клиента. **Покрытие по РФ-домену снова не проверяемо без платного ключа.**

### Прочие имена — не проверял вживую, встречаются только в маркетинговых сравнениях
В поисковой выдаче массово всплывают Context.dev, BrandApi/BrandsAPI, Quikturn, Brand.dev, MiroMiro — судя по стилю текста («Winner:», таблицы «Quick Comparison», FAQ-блоки под каждую статью), это, вероятно, SEO/маркетинговый контент, часть которого может быть сгенерирована ИИ самими конкурирующими сервисами друг про друга. Ни один из них я не открывал напрямую и не тестировал — **не проверено, не беру в качестве источника фактов**, только как сигнал «эта категория существует и активно конкурирует».

### Итог по направлению 1
Ни один Brand API не проверен на РФ-покрытие фактически — оба реалистичных кандидата (Logo.dev, Brandfetch) требуют платного ключа для Brand-данных (цвета/шрифты), а бесплатный Logo-эндпоинт без ключа тоже не открылся ни у одного (401/302). Это **дыра, а не отрицательный результат**: возможно, покрытие есть, возможно, нет — без ключа не узнать. Помечаю `needs validation`, а не «направление мертво».

## 2. Извлечение фирменного стиля из живой страницы своими силами

Здесь я не читал документацию, а **вживую скачал главные страницы шести настоящих российских компаний** (curl с реальным User-Agent, 27.07.2026) и для Wildberries дополнительно открыл страницу через настоящий браузерный движок (Browser pane), чтобы проверить, отличается ли поведение антибот-защиты для скрипта против реального рендерера.

| Домен | HTTP | Что нашли | Оценка |
|---|---|---|---|
| `sber.ru` | 200, но страница — это 2 КБ JS-заглушка, редиректящая на `sberbank.com/sberprime` | `theme-color` = `#000000` (общий, не бренд-зелёный Сбера), `og:image` — сезонная праздничная картинка `/holiday/og.png` | **Домен не ведёт на реальный продукт** — идентичность из него не извлечь в принципе |
| `tbank.ru` (Т-Банк, экс-Тинькофф) | 200 (после редиректа на `www.tbank.ru`), полноценная страница 1.79 МБ | HTML `theme-color` = `#ffffff` (вводит в заблуждение — это НЕ бренд-цвет); но `/manifest.webmanifest` (200 OK) содержит `"theme_color": "#ffdd2d"` и `"background_color": "#ffdd2d"` — это и есть настоящий фирменный жёлтый Т-Банка | **Успех через manifest.json**, при этом `theme-color` из HTML сам по себе — ложный сигнал |
| `alfabank.ru` | 200 | `/manifest.json` (200 OK) содержит `"theme_color": "#f03226"` — близко к известному фирменному красному Альфа-Банка | **Успех через manifest.json** |
| `vtb.ru` | 200, полноценная страница 248 КБ | Есть `apple-touch-icon` и `og:image` (векторные/растровые иконки), но `theme-color` в HTML не найден, а `<link rel="manifest">` указывает на `/manifest.webmanifest`, который отдаёт `404` | **Частичный результат**: иконки есть, цвета нет; нужен был бы анализ доминирующего цвета иконки — то есть снова «измерение», просто по маленькой чистой картинке, а не по скриншоту экрана |
| `wildberries.ru` | curl: `HTTP 498` (кастомный код); реальный браузер: страница-заглушка антибота | И curl, и полноценный браузерный рендер получили один и тот же экран `/__wbaas/challenges/antibot/` с текстом «Подозрительная активность… Новая попытка через 00:46», ID сессии и IP видны в ответе | **Заблокировано технически**, причём подтверждено, что блокирует не только curl, но и настоящий браузерный движок без решения капчи |
| `ozon.ru` | Циклический `HTTP 307` редирект с растущим параметром `__rr=` (1 → 7…), финальный контент не получен в пределах теста | Похоже на анти-бот редирект-цикл, но диагноз не завершён | **Неубедительно / не проверено до конца** |

Вывод по строкам: **2 из 6 доменов дали точный бренд-цвет без всякой интерпретации** — просто прочитал JSON. Это ровно закрывает ту дыру, которую эксперимент со скриншотом назвал главной проблемой («интерпретируемое — назначение семантических ролей цветам»): `theme_color` в манифесте — это уже готовая семантическая роль от самого бренда, а не наша догадка.

Инструментарий для этого пути не нужен экзотический: Playwright уже стоит в проекте, но для этой конкретной проверки хватило обычного HTTP-запроса (`curl`/`fetch`) к `/manifest.json`, `/manifest.webmanifest`, и к самой HTML-странице за метатегами `theme-color`, `og:image`, `apple-touch-icon`. Открытая библиотека **OpenBrand** (`github.com/tight-studio/OpenBrand`, MIT, 777 звёзд на момент обращения 27.07.2026) уже реализует ровно этот набор шагов как npm-пакет (`npm add openbrand`) и как MCP-сервер: читает `theme-color`, `manifest.json`, доминирующие цвета логотипа, og:image, favicon/apple-touch-icon, название бренда из `og:site_name`. Статья с разбором его ограничений (dzone.com, автор — по всей видимости сам разработчик OpenBrand) прямо называет главную проблему, которую я тоже увидел вручную: **«Color extraction conflates brand color with design system color… OpenBrand currently returns both without distinguishing between them»** — то есть даже когда манифест есть, отличить «цвет бренда» от «просто акцентный цвет UI» — отдельная нерешённая задача даже у специализированного инструмента. Библиотеку саму не запускал (не тестировал живьём), только прочитал её README и разбор — это `не проверено`, только документация.

## 3. Извлечение дизайн-токенов из CSS

Проверено вживую слабее остальных разделов из-за приоритета сдачи файла — фиксирую честно.

- **`@projectwallace/css-analyzer`** — открытый (MIT) npm-пакет, страница `npmjs.com/package/@projectwallace/css-analyzer` открыта и прочитана (27.07.2026). Работает **статически**: на входе — уже полученный текст CSS, на выходе — структурированный объект ровно с нужными нам категориями: `colors`, `fontSizes`, `fontFamilies`, `lineHeights`, `gradients`, `textShadows`, `boxShadows`, `borderRadiuses`, длительности и тайминг-функции анимаций, используемые CSS-юниты — каждая категория с `total`/`totalUnique`/`uniquenessRatio`. Формат вывода для радиусов и цветов близок к спецификации Design Tokens (DTCG-подобный, с `$type`/`$value`/`$extensions`), что подтверждено соседним репозиторием `github.com/projectwallace/css-design-tokens`. **Важное ограничение по конструкции инструмента**: он не читает `manifest.json` и не резолвит `var(--custom-property)` до финального значения, если сама CSS-переменная объявлена в другом месте таблицы стилей неочевидным образом или собирается во время сборки (CSS-in-JS). Когда я вручную грепал скачанный HTML `tbank.ru` на паттерн `--*color*: #hex`, нашёл только служебные токены вида `--tui-button-background-color:#0000` (прозрачные/пустые) — реальный фирменный `#ffdd2d` в статическом HTML-дампе простым регэкспом не обнаружился, хотя из `manifest.json` того же домена он достался мгновенно и точно. Это значит: для SPA с runtime-темизацией **путь через сырой CSS может оказаться сложнее и ненадёжнее**, чем путь через `manifest.json`, вопреки исходному предположению задания «значения там записаны, а не измерены» — они действительно записаны, но не обязательно в статическом CSS-файле, доступном без выполнения JS.
- **Хостинг-версия Project Wallace** (`projectwallace.com/design-tokens`, `projectwallace.com/analyze-css`) — по описанию на сайте принимает вставленный URL или сырой CSS прямо в браузере и извлекает те же категории токенов. **Не тестировал вживую** ни на одном домене — это осталось непроработанным из-за приоритета сдачи файла, честно помечаю как пробел, а не как факт.
- **CSS Stats (`cssstats.com`)** — сайт открывается (`cssstats.com`, `/api`, `/browse`, `/docs/api` — все страницы отдали ответ при обращении 27.07.2026), футер показывает диапазон «2013–2026», то есть проект жив дольше десятилетия и не выглядит заброшенным. **Содержимое анализа ни разу не получено** — Tavily вернул только заголовки страниц без текста, углублённо не проверял. Статус: жив, но не протестирован.
- Обобщённое имя «css-analyzer» из задания, видимо, и есть `@projectwallace/css-analyzer` — отдельного одноимённого популярного инструмента с других не найдено.

## 4. Ограничения подхода

Все пункты ниже — либо прямое эмпирическое наблюдение сегодняшних тестов, либо прямо документированное чужое ограничение; ничего не додумано.

1. **Домен подрядчика может не вести на реальный продукт.** Живой пример — `sber.ru`: это не «сайт Сбербанка», а редирект-заглушка на `sberbank.com/sberprime`. Для любого подрядчика с похожей схемой (маркетинговый домен ≠ продуктовый домен, ≠ платёжный поддомен) извлечение по «домену» без знания правильного поддомена/URL бессмысленно.
2. **`theme-color` в HTML — ненадёжный сигнал бренд-цвета.** Т-Банк отдаёт в HTML `#ffffff` (цвет UI-хрома этой конкретной страницы), а настоящий бренд-жёлтый `#ffdd2d` лежит только в `manifest.json`. Если тянуть только meta-тег, получаем неверный «измеренный, но не тот» цвет — тот же класс ошибки, который эксперимент со скриншотом уже поймал на интерпретации.
3. **`manifest.json`/`manifest.webmanifest` может отсутствовать или быть битым.** У ВТБ файл заявлен в `<link rel="manifest">`, но реально отдаёт `404` — путь «прочитать манифест» не универсален даже среди топ-10 банков РФ.
4. **Анти-бот защита блокирует не только скрипты, но и настоящие браузеры.** Wildberries отдал один и тот же экран проверки «Подозрительная активность» и обычному curl-запросу, и полноценному браузерному рендерингу через Browser pane (без решения капчи и без остаточных cookies/сессии реального пользователя ни один автоматический заход не проходит). Ozon вёл себя похоже (циклические 307-редиректы). Для крупного e-commerce в РФ это значит: наивный HTTP-запрос или headless-браузер без warm-up сессии/остаточных cookies/резидентного прокси **не пройдёт** дальше страницы проверки — а это именно тот класс подрядчиков (интернет-магазины), где платёжный экран нужнее всего.
5. **PWA-манифест описывает бренд всего сайта, а не конкретно платёжный экран.** Даже когда `theme_color` извлечён верно (Т-Банк, Альфа-Банк), это глобальный цвет всего мобильного/PWA-опыта компании — само задание фокусируется на **платёжном экране**, который у крупного игрока вполне может иметь собственную, отличную от общесайтовой, палитру (например, у эквайринг-виджета/платёжного шлюза, встроенного через iframe стороннего провайдера). Этого я не проверял ни на одном домене — логическое ограничение, не эмпирическое.
5б. Отдельно: даже там, где найден правильный цвет, не решена задача, которую сам разработчик OpenBrand называет нерешённой и у себя — «цвет бренда» и «акцентный цвет дизайн-системы конкретного экрана» могут не совпадать, а инструменты (включая наш ручной путь через манифест) их не различают.
6. **Небольшой бизнес может не иметь ни манифеста, ни осмысленного `theme-color`, ни вообще активного домена.** Из протестированного набора видно расслоение: у топ-банков (Т-Банк, Альфа-Банк) манифест есть и корректен, у крупного e-commerce — либо антибот, либо не проверено, у одного банка манифест сломан. Малый подрядчик, скорее всего, ближе к «нет манифеста вообще», чем к «манифест есть и корректен» — это экстраполяция из выборки в 6 доменов, а не измеренный факт про малый бизнес, поэтому явно `needs validation`.
7. **Санкционный контекст для коммерческих Brand API остаётся неясным, не разрешён в этом ресёрче.** Найден только общий материал о санкциях США на ИТ-консалтинг/дизайн-услуги для России (DLA Piper, 2024) с оговоркой об исключении для бесплатных общедоступных веб-приложений — не нашёл ничего, что прямо говорит про Brandfetch/Logo.dev и Россию в любую сторону. Это `needs validation`, не факт ни за, ни против.

## Применимость к российским подрядчикам

Итоговая оценка по прямым сегодняшним замерам (не по обещаниям):

- **Собственное извлечение (`manifest.json` + `theme-color` + иконки) — рабочий, но частичный сигнал.** 2 из 6 доменов (Т-Банк, Альфа-Банк) дали точный бренд-цвет без интерпретации. 1 из 6 (Сбер) — домен не ведёт на продукт. 1 из 6 (ВТБ) — манифест сломан, есть только иконки. 2 из 6 (Wildberries, Ozon) — блокировка/неубедительный ответ на уровне сети, до анализа контента дело не дошло.
- **Коммерческие Brand API по РФ-доменам — полностью не проверены.** Оба реалистичных сервиса (Logo.dev, Brandfetch) отказали в бесключевом доступе (401 и 302 соответственно) на тестовом РФ-домене. Открытых данных о фактическом покрытии `.ru`/`.рф` не нашёл ни у одного вендора и ни в одном независимом источнике. Нельзя ни подтвердить, ни похоронить это направление — это честная дыра в доказательной базе, закрыть её может только реальный платный ключ и тест на выборке настоящих доменов подрядчиков.
- Изначальная гипотеза задания («у большинства компаний есть сайт со стилями, доступными машинно без распознавания картинок») **верна примерно для трети протестированной выборки** — не для «большинства» в буквальном смысле, и это именно банки/финтех, у которых уже есть культура PWA-манифестов. Для розницы (Wildberries, Ozon) главным барьером оказалась не отсутствие бренд-данных, а активная защита от автоматического доступа.

## Что берём

- **Пробовать `manifest.json`/`manifest.webmanifest` + `theme-color` meta + `apple-touch-icon`/`og:image` как первый, самый дешёвый шаг** до скриншота — извлечение бесплатно (просто HTTP GET), не требует ни одного платного API-ключа, и там, где манифест есть и не сломан, даёт точный, а не измеренный-с-ошибкой цвет.
- **Не полагаться на `theme-color` из HTML в одиночку** — он может врать (кейс Т-Банка); всегда сверять с `manifest.json`, если он есть, отдавая манифесту приоритет.
- **Скриншот остаётся обязательным fallback**, а не альтернативой — минимум для трёх реальных сценариев из шести протестированных: домен-заглушка (Сбер), сломанный манифест (ВТБ), анти-бот блокировка (Wildberries/предположительно Ozon).
- **Прежде чем встраивать Brandfetch или Logo.dev в пайплайн — получить пробный платный ключ и прогнать реальный список доменов подрядчиков** (в том числе несколько `.ru`) до принятия решения: сейчас купить/не купить нельзя обосновать, покрытие неизвестно.
- **CSS-токен-инструменты (Project Wallace и аналоги) — не приоритет для SPA-тяжёлых сайтов**: ручная проверка показала, что нужный цвет у Т-Банка лежит в `manifest.json`, а не восстанавливается тривиально из статического CSS/HTML-дампа той же страницы. Если возвращаться к этому направлению, тестировать `@projectwallace/css-analyzer` нужно на CSS, полученном после полной отрисовки страницы (через Playwright), а не на «сыром» HTML-дампе.
